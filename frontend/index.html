ML METHODOLOGY

MODEL DETAILS

Understanding the XGBoost classifier behind ExoHabitAI's predictions.

🤔 Why XGBoost?

Class Imbalance Handling

The dataset has only 27 habitable planets out of 6,100 (0.44%) — a severe class imbalance. XGBoost's scale_pos_weight=220 parameter directly penalises the model for missing habitable planets, making it recall-optimised for the minority class.

Tabular Data Performance

XGBoost consistently outperforms neural networks and linear models on structured tabular data. Our dataset has 31 engineered features including scaled numerics, spectral type encodings, and custom habitability indices — exactly where gradient boosting excels.

Interpretability

Unlike black-box deep learning models, XGBoost provides native feature importance scores. This is critical for scientific use: astronomers can see exactly which parameters (habitability score: 49.3%, eq. temperature: 21.5%) drive predictions.

Comparison Results

XGBoost achieved F1=1.0 and ROC-AUC=1.0 on the test set — outperforming Logistic Regression (F1=0.21), Decision Tree (F1=0.60), and Random Forest (F1=0.57) across all metrics after hyperparameter tuning.

⚙️ How It Was Trained

01
Data Collection

6,100 confirmed exoplanets sourced from the NASA Exoplanet Archive. Features include radius, mass, orbital period, equilibrium temperature, stellar luminosity, temperature, and metallicity.

02
Feature Engineering

Three custom indices created: Habitability Score Index (composite planetary-stellar metric), Stellar Compatibility Index (host star influence), and Orbital Stability Index. Star spectral types were one-hot encoded into 8 binary columns.

03
Preprocessing Pipeline

Scikit-learn Pipeline with ColumnTransformer: SimpleImputer (median) for 4,559 missing values, StandardScaler for 23 numeric columns, and OneHotEncoder for the star_spectype categorical column.

04
Train-Test Split

80/20 stratified split (stratify on habitable_binary to preserve the 0.44% class ratio). Training: 4,880 rows (22 habitable). Test: 1,220 rows (5 habitable).

05
Baseline Models

Logistic Regression and shallow Decision Tree trained first as benchmarks. Logistic Regression achieved F1=0.21 (high recall, poor precision). Decision Tree achieved F1=0.60 with class_weight='balanced'.

06
Primary Model Training

Random Forest (200 trees, class_weight='balanced') and XGBoost (200 estimators, scale_pos_weight=220) trained on full training set. XGBoost achieved ROC-AUC=1.0 on test with perfect precision and recall.

07
Hyperparameter Tuning

RandomizedSearchCV with 5-fold StratifiedKFold (40 iterations each). Best XGBoost params: n_estimators=400, max_depth=10, learning_rate=0.1, subsample=0.8, colsample_bytree=0.7. Best CV F1 = 0.931.

08
Final Selection & Saving

XGBoost selected as final model (highest F1 + no overfitting). Saved as models/final_model.pkl using joblib. Also saved random_forest.pkl and xgboost_best.joblib for comparison.

PROJECT INFO

ABOUT ExoHabitAI

An end-to-end ML pipeline for exoplanet habitability classification.

🌌

The Problem

Of 5,000+ confirmed exoplanets, identifying potentially habitable ones requires expensive telescopic observation. ExoHabitAI uses ML to pre-screen candidates, helping astronomers prioritise observation targets.

📡

Data Source

NASA Exoplanet Archive — 6,100 confirmed exoplanets with parameters spanning radius, mass, orbital mechanics, stellar properties, and derived habitability indices.

🤖

XGBoost Model

Gradient-boosted decision trees with scale_pos_weight=220 to handle severe class imbalance (only 0.44% habitable). Achieves F1=1.0 on the test set.

🔧

Pipeline

Sklearn Pipeline: ColumnTransformer (imputation + scaling + OHE) → XGBClassifier. No data leakage. Handles missing values automatically via median imputation.

🌐

REST API

Flask backend with 6 endpoints: /predict, /predict/batch, /rank, /stats, /features, /health. CORS enabled for frontend integration.

🎯

Key Insight

Habitability Score Index (engineered feature) contributes 49.3% of prediction importance — confirming that composite metrics outperform individual raw measurements.
